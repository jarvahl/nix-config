# Composing Den aspects

This repository uses Den's resolved-tree introspection for conditions between
aspects. Do not scan `den.aspects` during module evaluation and do not use
`hasAspect` to decide an `includes` list.

## Core pattern

Put conditional configuration in the class module that owns it:

```nix
den.aspects.git.hjem =
  { user, ... }:
  lib.mkIf (user.hasAspect den.aspects.certificates) {
    # Hjem configuration enabled only when certificates is present.
  };
```

Use `host.hasAspect` in `.nixos` modules and `user.hasAspect` in `.hjem` or
other user-class modules. `hasAspect` reads the resolved tree, so it also sees
aspects generated by Den.

## Providers

Use `provides` for routing configuration between entities, not for discovering
or activating aspect extensions:

```nix
den.aspects.example.provides.to-hosts.nixos = { host, ... }: {
  # Configuration delivered to the host.
};
```

## Rules

- Never enumerate `den.aspects` with `mapAttrsToList`, `filterAttrs`, or similar
  reflective scans during module evaluation.
- Never use `hasAspect` inside `includes`; that creates a cycle because
  `includes` participates in building the tree.
- Keep independent aspects in separate top-level attrsets.
- Use `.hjem` for user/home configuration and `.nixos` for host/system
  configuration.
- Keep attribute keys alphabetically sorted.
- Prefer `inherit (den.aspects) name;` and `inherit (lib) mkIf;` for local
  references where it improves readability.
- Keep SOPS declarations in the extension that consumes them.

## Resolved-tree introspection

Inside class modules, use `host.aspects`, `user.aspects`, or `home.aspects` when
an aspect must be located by identity or metadata. Prefer `hasAspect` when the
aspect reference is known statically.

## Workflow

1. Inspect the owning aspect and its current class module.
2. Put the conditional configuration in that module with `lib.mkIf`.
3. Use `provides` only when the configuration must cross host/user boundaries.
4. Remove obsolete reflective extension policies instead of adding another
   global scanner.
5. Stage moved or newly created source files before evaluating the flake.
6. Run formatting and a targeted host build.
